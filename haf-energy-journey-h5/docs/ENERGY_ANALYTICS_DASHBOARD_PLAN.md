# HAF 探索本心：轻量数据看板方案

版本：v1.0  
日期：2026-08-23  
状态：本地 Demo 已实现

## 1. 看板只回答三个问题

1. 有多少用户访问过探索本心模块？
2. 有多少用户通过这个模块收藏过课程？
3. 一共产生了多少次收藏？

不在这份看板里分析 DeepSeek、Prompt、灵数、脉轮或推荐算法效果。

## 2. 三个核心数字

| 指标 | 定义 |
| --- | --- |
| 访问用户数 | 在所选时间范围内打开或看到模块的去重用户数（UV） |
| 收藏用户数 | 在模块内成功收藏至少一节课程的去重用户数 |
| 收藏总量 | 在模块内成功产生的收藏次数；同一用户收藏三节课计三次 |

可以补充一个自动计算的小指标：

```text
访问后收藏率 = 收藏用户数 / 访问用户数
```

它只用于快速判断模块是否带来收藏，不需要做复杂归因或实验分析。

## 3. 单页看板布局

当前顶部日期筛选为今天、近 7 天、近 30 天和全部；自定义范围留到生产看板。

第一排三张数字卡：

- 访问用户数
- 收藏用户数
- 收藏总量

第二排：

- 一张趋势图：每天的访问用户数与收藏用户数
- 一个醒目的访问后收藏率

第三排课程明细：

| 课程名称 | 收藏用户数 | 收藏次数 |
| --- | ---: | ---: |

课程明细用于看清楚用户最终把哪些课程收进了收藏，不分析为什么收藏。

## 4. 最小埋点

只需要两个事件：

| 事件 | 触发时机 | 必要字段 |
| --- | --- | --- |
| `energy_module_viewed` | 模块实际打开或进入可视区域 | `user_id`, `event_time` |
| `energy_course_favorited` | 收藏接口确认成功 | `user_id`, `course_id`, `event_time`, `source=energy_journey` |

注意：

- 收藏必须在收藏接口返回成功后再计数。
- 同一次点击失败或重复上报不能重复计数，建议携带唯一 `event_id`。
- 取消收藏不减少历史“收藏总量”；如果以后需要查看当前净收藏数，再增加 `energy_course_unfavorited`。
- 看板不保存生日、罗盘坐标、灵数、脉轮或推荐理由。

## 5. 后端最小数据结构

访问记录：

```json
{
  "event_id": "evt_xxx",
  "event_name": "energy_module_viewed",
  "user_id": "anonymous_or_hashed_user_id",
  "event_time": "2026-08-22T10:00:00+08:00"
}
```

收藏记录：

```json
{
  "event_id": "evt_xxx",
  "event_name": "energy_course_favorited",
  "user_id": "anonymous_or_hashed_user_id",
  "course_id": "course_xxx",
  "source": "energy_journey",
  "event_time": "2026-08-22T10:03:00+08:00"
}
```

这套数据已经足够生成第一版看板，后续只有在确实需要研究用户在哪一步离开时，再增加流程漏斗事件。

## 6. 当前实现边界

- 本地服务每 5 秒刷新聚合数据。
- 事件写入 `haf-energy-dashboard/data/events.jsonl`。
- Dashboard 与收集器未鉴权，只能用于本机 Demo。
- 快照不复制 `events.jsonl`，避免把测试或用户数据带入版本包。
- 正式上线必须使用数据库唯一约束做 `event_id` 去重，并给看板增加登录与权限。
