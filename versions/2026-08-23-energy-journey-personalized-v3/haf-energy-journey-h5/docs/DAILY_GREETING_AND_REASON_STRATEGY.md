# HAF 每日问候与课程推荐理由策略

版本：v1.0  
日期：2026-08-23
状态：每日 AI 问候已实现；真实课程 API 与当次 AI 推荐理由待接入

## 1. 每日问候为什么可以变化

用户完成首次建档后，系统已经拥有生日。进入每个新的自然日时，可以根据用户生日、当天日期和产品时区确定 `personal_day`，把它作为当天问候的主题。

问候发生在罗盘感应之前，所以它只能表达“今天的主旋律”，不能提前声称知道用户此刻的方向、脉轮或情绪。

流程：

```text
生日 + 当天日期
        ↓
Personal Day 1-9
        ↓
当天问候主题
        ↓
开始今日感应
        ↓
罗盘补充此刻能量
```

## 2. 本地每日问候兜底

| Personal Day | 主题 | 问候主句 | 补充句 |
| ---: | --- | --- | --- |
| 1 | 开始 | 今天，有一束新的力量正在靠近。 | 不必准备得完美，先听听自己想从哪里开始。 |
| 2 | 连接 | 今天，适合给感受多一点被听见的空间。 | 慢一点，也许你会看见自己真正想靠近的关系。 |
| 3 | 表达 | 今天，有些感受正在寻找自己的声音。 | 不急着说得完整，先让它被你自己听见。 |
| 4 | 安定 | 今天，先让自己回到脚下这一步。 | 当身体有了支撑，心里的方向会更清楚一些。 |
| 5 | 流动 | 今天，允许新的可能轻轻松动边界。 | 不必马上决定，让感受先自由地流过。 |
| 6 | 关照 | 今天，也把一份温柔留给自己。 | 在回应外界之前，先听听你真正需要什么。 |
| 7 | 照见 | 今天，答案可能藏在更安静的地方。 | 放慢一点，让重要的线索自己浮现。 |
| 8 | 力量 | 今天，适合把能量收回一个清晰的选择。 | 不必做很多，只需站稳真正重要的那一步。 |
| 9 | 放下 | 今天，适合为已经完成的部分留一点空白。 | 轻轻放下，新的方向才有空间慢慢出现。 |

界面保持文字问候，不重新加入能量球：

```text
8月23日 星期日
欢迎回来

今天，也把一份温柔留给自己。
在回应外界之前，先听听你真正需要什么。

[ 开始今日感应 ]
```

当前版本会在初始化 Loading 阶段请求 DeepSeek，生成 14–30 字的每日问候标题；上表主句是接口不可用、超时或格式无效时的本地兜底。补充句每个数字已有三组本地变体，使用日期和用户资料稳定轮换。

前端等待最多 6 秒。无论最终采用 AI 还是本地文案，都会在进入问候页之前锁定并缓存；问候页出现后不再异步替换文字。

当前缓存签名：

```text
前端：日期 + Personal Day + Life Path + prompt version
后端：匿名用户 + 日期 + Personal Day + Life Path + 每日表达切面 + prompt version
```

修改生日后，只要 Personal Day 或 Life Path 变化，就不会复用旧问候。相同签名在同一天保持稳定。

DeepSeek 只接收已经计算好的数字和匿名键，不接收生日、性别、城市或出生时间。

## 3. DeepSeek 与课程推荐理由

不建议在拿到课程后，为每门课只批量生成一条最终推荐理由。那条理由与具体用户无关，会显得僵硬。

推荐采用两层结构：

### 离线批量层

课程 API 更新后，批量处理每门课：

- 从真实介绍中提炼练习方式、适合的能量方向和可用关键词
- 生成结构化课程标签
- 提炼可以安全引用的课程内容片段
- 人工抽查后存入课程推荐索引

这层可以使用 DeepSeek，只有课程内容变化时才重新运行。

### 用户当次生成层

用户完成罗盘后，再把以下信息组合：

- 当天 Personal Day 的主旋律
- 罗盘得到的此刻入口
- 主要脉轮线索
- 被选中课程的真实介绍与离线标签

一次生成三条最终推荐理由。DeepSeek只负责组织语言，不能添加课程介绍里不存在的功效。

```text
当天主旋律 + 此刻入口 + 脉轮线索 + 课程事实
                        ↓
              当次专属推荐理由
```

## 4. 当前实现与下一步

当前 Demo：

1. 规则层先从 15 节 Demo 课程中选出三节。
2. 推荐理由由确定性模板组合今日主题、此刻关键词、主脉轮和课程事实。
3. AI 能量解读与课程选择相互独立；AI 失败不会改变课程列表。

真实课程 API 接入后：

1. 课程接入时用 DeepSeek批量生成结构化标签，不生成最终展示句。
2. 系统先用规则选出三节课程。
3. 每次感应最多调用一次 DeepSeek，同时生成三条推荐理由。
4. 相同的用户、日期、罗盘结果区间和课程版本可以读取缓存。
5. DeepSeek 超时就使用现有规则模板理由，页面仍可正常出现。

这样既不会把系统做成固定话术，也不会让每个页面步骤都依赖 DeepSeek。
